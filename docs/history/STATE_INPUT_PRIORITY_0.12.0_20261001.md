## Input research / rejected approach

work/input_priority_research/ preserves static notes/disassembly. Import-name parsing of both captured images yields no ordinary USER32 entries: captures omit packed import pages, file PE tables use protected stubs; hardcoding an IAT slot or an assumed GetRawInputData export would be weak evidence. Engine reader0x616d00 is the sole GetRawInputData callsite in the preserved code; it processes raw mouse movement, not buttons. Window handler0x615a10 dispatches keyboard and ordinary mouse down/up (button helpers0x616b10/0x616b70), forwarding WM_INPUT to the movement reader. These addresses are RESEARCH ONLY and are not added to the addon.

Chosen input interception uses public Windows own-window subclass APIs, no game version/address dependency. Primary documentation: [SetWindowLongPtrW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowlongptrw), [GetRawInputData](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getrawinputdata), [RAWMOUSE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse). All unhandled messages forward through CallWindowProcW; raw mouse movement is unchanged. No global keyboard/mouse hook, input injection, game-text patch, VirtualProtect or WriteProcessMemory in the new native helper.
