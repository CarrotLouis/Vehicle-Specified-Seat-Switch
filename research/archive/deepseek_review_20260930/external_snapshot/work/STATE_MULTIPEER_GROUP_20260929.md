# Multiplayer capability group split; production still carries the inverted weapon-seat flag

Round scope: objective step 2, second slice. Adds authored source, one new capability group and two verification layers. No ZIP was built, no shipped package changed, no live game/config/profile/Arsenal change, and no user-project file was touched.

Problem found before writing any wiring: routing_spec.lua and authority_spec.lua each end with `spec.records[name]=d; spec.core[#spec.core+1]=name`. compat.lua resolves spec.core unconditionally, so chaining them onto the production spec would have made Normal require roughly thirty extra native signatures (route_* and authority_*), and any single Enhanced-only mismatch would then have disabled Normal as well. That is precisely the design debt recorded in STATE_UPDATE_25480438_20260924.md ("native.lua eagerly binds many Enhanced interfaces even for Normal. An Enhanced-only interface mismatch can unnecessarily disable Normal too", proposed fix "separate required capabilities: Normal, Enhanced, and read-only network recorder; defer Enhanced-only bindings until needed").

Added work/seat_switch/src/multipeer_spec.lua: records #spec.core, runs both augmenters, then moves every name they appended out of spec.core and into spec.multipeer, leaving core, enhanced and engine byte-identical. spec.edges is deliberately left alone because compat.lua's edges() only checks an edge when both endpoints are already resolved, and nothing outside the group resolves these records, so those edges stay inert until the group is requested - at which point edges() runs for them inside the extra-group phase. Recomposition is idempotent: a second run re-appends the same names and they are recognised as already present instead of duplicated. trace_points are wired into profile.functions by the same call so production composition is one step. Augmenters and trace points are injected, so the module never hardcodes a path.

Changed work/seat_switch/src/compat.lua additively: M.start gains an optional seventh parameter extra_groups. Requested names are pre-initialised to false on output.capabilities, appended to the relocation scanner's group list, and resolved inside a separate pcall after the Enhanced phase, setting output.capabilities[group]=true on success or extra_reason plus log('extra_capability_unavailable ...') on failure. Unrequested groups stay nil rather than false, so callers can distinguish "not asked for" from "refused". With extra_groups nil - every existing call site - behaviour is unchanged.

Verification 1, spec level (tests/test_multipeer_spec.lua): core/enhanced/engine identical before and after composition (core 14 names), 24 witnesses collected (6 route_*, 18 authority_*) with no foreign names, every witness carries an rva hint on its own module, 8 trace points wired, recomposition idempotent.

Verification 2, end to end (tests/test_multipeer_capture.lua, run against BOTH preserved captures over the read-only mock address space): normal resolves exactly 14 base names and capabilities.multipeer stays nil; enhanced-solo resolves 33 names with the group still unrequested; requesting the group adds exactly its 24 witnesses (checked 33->57); and the decisive property - zeroing one byte of the multipeer-only witness authority_send leaves capabilities.normal=true and capabilities.enhanced=true while multipeer=false with interface_not_compatible_authority_send. Results are identical on capture-25480438 and capture-25327279, and the 14 base names match the checked=14 in the real gameplay runtime log.

Suite: 13/13 Lua tests PASS, plus the new capture test on both builds. build_gameplay.py's test list now includes test_multipeer_spec.lua and runs test_multipeer_capture.lua once per preserved capture; the script gained the os import that env needs and was py_compile checked.
