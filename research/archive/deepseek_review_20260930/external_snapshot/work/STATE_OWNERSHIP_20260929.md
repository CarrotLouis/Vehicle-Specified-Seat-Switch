# Ownership branch policy added; production still carries the 0.8.0-style inverted flag

Round scope: first slice of objective step 2 (production integration). No ZIP was built and no shipped package changed; this round adds authored source plus an exhaustive offline test. No live game/config/profile/Arsenal change; no user-project file touched.

Added work/seat_switch/src/ownership.lua: pure ownership-branch decision logic with no native calls, no I/O and no module state, so every decision is taken from freshly captured state and a refusal never mutates anything. It encodes the three branches the validated experiment lacked: keep (the local peer already owns the chassis: no borrow and no hand-back, whatever the destination role), borrow (borrow from the single remote owner, then hand the chassis back to that same peer), retain (taking an empty driver seat keeps the borrowed authority instead of returning it). M.plan(s,target) returns {action,acquire,handback} or nil plus a reason; M.can_return(s,ticket) decides the hand-back separately so extra peers can never block cleanup while a changed, local or reassigned driver always does (matching the validated adapter's rule that a later joiner must not prevent returning authority); M.ticket binds an operation to the identities it was planned against. Refusal precedence is fixed and tested: invalid_target, already_seated, occupied/unknown_occupancy, authority_changing, then the ownership branches. Unknown occupancy is never treated as empty.

Added work/seat_switch/tests/test_ownership.lua and wired it into build_gameplay.py's test list, which is the suite the release pipeline depends on (build_release.py bundles from src but only syntax-checks, so build_gameplay.py is where unit tests run). Result: 1728 matrix cases (108 keep, 18 borrow, 6 retain, 1596 refused) plus targeted branch, refusal, return and ticket cases. Coverage note: the first version iterated ipairs({false,true,nil}), which stops at the nil and silently skipped unknown occupancy entirely; it now iterates named states so all three occupancy cases are exercised. Branch counts verify by hand: keep = 3remotes x 3player-counts x 4nodes x 3off-node-targets = 108; borrow = 1 x 2(player 2/3) x 9 = 18; retain = 1 x 2 x 3 = 6.

Full gameplay Lua suite re-run: 12/12 PASS (policy, ownership, input, config/controller, config storage, snapshot, native, driver, pose, entry, platform, syntax). test_platform.lua initially failed on a STALE generated fixture - work/seat_switch/tests/lua51.sha256 held 11b726a70cccaf115969d8d68519fe1fe20cf4a955c2894128fb6254f7add92c while the installed F:/SteamLibrary/steamapps/common/Helldivers 2/bin/lua51.dll is 2c8720c9f446c848436ad993b1a88099d76f0b0b09df53689719b797c3039ce7. build_gameplay.py regenerates that file (line 12) before running tests, so this is a manual-run artifact rather than a regression; the fixture was regenerated in the mirror and the suite is 12/12.

IMPORTANT FINDING, not yet acted on: production work/seat_switch/src/native.lua lines 126-128 contain the same defect that 0.8.1 fixed in the experiment - `if (s.vehicle=='m102' or s.vehicle=='m104') and s.profile.roles[s.node+1]==2 then rotation(nil,s.avatar,true) end`. It writes the per-avatar vehicle-attachment flag to true when leaving a weapon seat (role 2), which is the state the user's live test showed as frozen facing with discrete snaps and local/remote aim disagreement. Note also that this same file already calls `remove_flag(s.avatar_address,44)` for maelstrom, which is exactly the engine's own `remove_avatar_flag(avatar,0x2c)` invoked immediately before the entry events 0xe8344235/0xd3a9222b - i.e. the engine-faithful detach path already exists here for one vehicle while m102/m104 use the boolean setter instead. Fixing native.lua is deliberately DEFERRED until the user's 0.8.1 retest confirms which value is correct, so a production change is not made on unverified evidence.
