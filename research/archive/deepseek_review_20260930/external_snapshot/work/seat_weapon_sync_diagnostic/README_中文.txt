Vehicle Specified Seat Switch — 0.9.9 消息替换版（联机，一次测试）

这一版只改一条消息，目标就是你要的三件事
你要的是：**座位正确且与所有人同步** + **从机枪位切走后解除对机枪的控制**。探头姿势这一轮**不管**。

关键推理（来自你的实测）
| 版本 | 回程发出 | 座位同步 | 人挂得上车 | 机枪 |
|---|---|---|---|---|
| 0.8.3 | `snapshot`+`transition` | ✅ | ✅ | ❌ 仍跟随 |
| 0.8.4 | 0.8.3 **+ `entry_request`** | ✅ | ❌ **定在原地** | ✅ 已解除 |

两者之间**只差 `entry_request` 这一条**，而你说得很清楚：**早期版本没有"定在原地"的问题**。

所以：`entry_request` 的语义是**"我进入了座位"** → 主机据此**重新挂载**角色 → 挂载模型与本地状态分叉。
**0.9.9 把它换成 `release_request`** —— 语义是**"我卸下了"**，只要求主机**释放武器**，不要求它重新挂载。

`release_request` 的签名已逐字节解出（薄包装 `0xbee380`，97 字节）：

```c
void (*)(uint64_t peer, uint32_t entity_id, uint32_t value)
// 载荷 = ( resolve(entity_id), &value )
// 本包发的是 (对端, 角色 id, 离开的座位号=4)
```

而且它**只是消息**，**不碰本地状态** —— 所以天然不会产生 0.8.4/0.9.8 那种损坏。

⚠️ 两条已封存、**都不要运行**
- **0.8.4**（会把人摘下车）
- **0.9.8**（会破坏挂载、无法切座）
- 本版**已彻底移除** 0.9.8 的 `owner_enter` 调用（我核对过代码里没有任何调用残留）
