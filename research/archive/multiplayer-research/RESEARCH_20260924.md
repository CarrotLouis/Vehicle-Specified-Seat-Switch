## Confirmed from existing native code
1. 0x637360 owner switch validates local collection ownership and handoff-busy state. It chooses a destination through next/previous adjacency. Its wire request at 0xbeb980 has hash 0xa7ece676 and four arguments: collection ref, avatar ref, current seat, direction. No exact cross-group target is present.
2. The owner releases/reserves through 0x6349b0 / 0x6344d0, broadcasts acceptance via 0xbe22b0, then handles authority via 0x635710. Host identity alone is not a substitute for vehicle ownership.
3. Snapshot hash 0xd4f97316 and transition hash 0xdcc32107 are native and therefore potential unmodified-peer-compatible messages. Their existence does not establish that reusing them for arbitrary cross-group moves is correct.
4. Seated restore 0x63eb10 writes collection/current/reserved/transition type, invokes entry/attachment action and completion, and resets action to -1 (0x63ec7e). It does NOT itself establish the new role. Note: older notes said it does not write action; the final disassembly shows that correction.
5. Transition receive 0x63ecc0 writes current, invokes action, sets deadline/transitioning/target. Earlier offline execution established role completion for synthetic ordered calls; network delivery, remote weapon/pose cleanup, sender authority and real handoffs were not tested.
6. Send 0xbde430 uses native interface indirection; -1 uses session peer array, -2 skips its first entry. Existing static capture does not prove what that first entry represents for each real host/client situation. Do not label it reliably 'exclude self'.
7. Current addon has explicit solo and local-ownership guards in native.lua and driver.lua. Removing guards alone cannot implement the missing protocol.
