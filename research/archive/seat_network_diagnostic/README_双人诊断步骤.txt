Vehicle Seat Network Diagnostic 0.1.2 — 载具换座联机只读诊断

这是本轮应使用的新包：Vehicle-Seat-Network-Diagnostic-0.1.2.zip
不是旧的 Vehicle-Seat-Diagnostic-0.1.1.zip，也不是联机加强版。
只在你的电脑记录数据，队友不需要安装本诊断包或换座模组。

安装
1. 关闭游戏，保留 Bingus Shared Loader v16。
2. 在 Arsenal 保留 Vehicle Specified Seat Switch 0.2.4，选择普通版 / Normal。
   这轮使用普通版来观察原生联机行为，按键仍使用你现有 INI 配置。
3. 替换旧联机诊断包 0.1.0/0.1.1，确保只启用本次 0.1.2；导入并启用本 ZIP 的“只读联机诊断”。旧 Vehicle Seat Diagnostic 0.1.0/0.1.1 保持禁用。
4. 默认优先级下 Loader 放在最下方，Purge / Deploy，然后启动游戏。
5. 开始记录不需要额外按键。每次游戏启动生成不同名字的日志，第二轮不会覆盖第一轮。

0.1.2 修复
旧联机诊断包与换座包在共享 Lua 环境中对 GetCursorInfo 使用不同结构体声明，导致换座包停止。
本版用诊断专属接口别名隔离声明；无需更新换座包 0.2.4 或修改 INI。
已用实际 LuaJIT/Windows 接口验证两种加载顺序，并做普通版、加强版共存的隔离部署检查。
诊断在单人和多人都可工作；本轮选普通版是为了采集原生联机基线。
进入双人采集前，先在单人 M-102 前排确认现有绑定能来回换座；若仍失效，停止并反馈。
尚未完成修复包的游戏内实测，以下双人步骤由你运行。

准备
找一位队友，仅双人。先只用 M-102 Gunner FRV，选择方便停车、敌人较少的任务。
无需在正在交战时测试；每一步停留约 3 秒，再进行下一步，便于对齐日志。
下文 F1/F2 等表示默认座位绑定；你已自定义时按自己的实际绑定。
让队友观察你是否正确坐在对应位置、驾驶和机枪是否由正确的人控制。
这轮不要求自动跨区域换座。需要换前后排或机枪位时，手动下车再进入该位置即可。

第一轮：你当房主（约 5 分钟）
A. 你单独坐驾驶位，队友站在车旁。F2 到副驾，F1 回驾驶，往返 3 次。
B. 队友坐驾驶位，你坐副驾。按你的“驾驶位”绑定 2 次，确认不会抢占队友座位。
   请队友正常下车，等 3 秒，再按驾驶位绑定进入驾驶位。
C. 交换：你驾驶、队友副驾。停车，双方按顺序下车，再让队友先驾驶、你再坐副驾。
   这一步用于观察控制权变化，不要把“房主”直接当成车辆拥有者。
D. 你进入后左/后右，F3/F4 往返 3 次；再让队友占据一个后排座位，尝试切入该占用位 2 次。
E. 你手动进入机枪位，队友驾驶；短暂转动车载枪并点射后松开，停留 3 秒再正常下车。
   随后你驾驶、队友使用机枪，短暂行驶再停车。记录是否有控制异常。
F. 双方离车后等 5 秒，正常退出游戏。记下这轮的大致时间和异常现象。

第二轮：队友当房主，你加入（约 5 分钟）
重新启动游戏，由队友开任务，重复 A–F。队友仍无需安装任何本项目模组。
退出游戏后，告诉本任务“联机诊断已完成”，说明哪轮由谁当房主、有无异常。
如果暂时只能做其中一轮，也说明已完成的是哪一轮。

日志位置
%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\
VehicleSeatNetworkDiagnostic.log：最新一次启动的状态。
VehicleSeatNetwork-日期-时间-进程号-计时值.log：本轮数据，一行一个 JSON 对象；每次启动独立保存。
状态文件出现 recording 表示已开始。正常退出在数据末尾写 end / shutdown。
出现 interface_not_compatible、inconsistent_global、ambiguous_interface 等错误时，说明必要接口未能通过校验，请停止测试并反馈。
checking_interfaces 表示正在校验；若地址移动，locating 后可能需等待数秒。文件指纹变化本身不再阻止采集。
长时间只有 waiting / read_gap 而无 mission 状态，也请反馈；不要反复尝试跨区操作。
每份数据日志上限约 32 MiB，达到上限停止记录。可退出再启动建立新日志。
此电脑上的 Codex 可以直接读取，无需上传或公开游戏文件。队友观察结果用文字描述即可。

记录内容与边界
记录玩家/连接数量、匿名 P1/P2 连接顺序、临时实体/网络单元编号、本机拥有标志、当前/目标/预留座位、
换座阶段与截止计时、空位掩码，以及支持车辆中配置的座位按键触发事件。
只读取现有 INI，不创建或修改按键配置；按键事件只记车型和座位名称，不保存键盘输入文本。
P1 不代表房主或自己；owned_local=false 也不直接指出是哪位队友拥有载具。
不读取聊天/账号凭据，不导出完整模块或堆内存，不修改游戏状态、不调用换座函数、不注入按键。
不抓取网络报文、不安装网络钩子、不发送自定义 RPC。记录的是本机观察到的联机状态，
不能单凭它证明远端收到的报文顺序、可靠性或完整姿态。这是联机研究第一阶段的数据。
原生 update/shutdown 回调继续执行；最多约每 16ms 采样，状态变化时记录，静止时每 2 秒记录一次。

验证范围
已做合成双人状态、过渡座位、占位变化、控制权标志、读到一半状态变化、异常边界和日志机制的离线验证。
已通过真实 Arsenal 后端的隔离导入/部署/移除检查，未改动正在使用的管理器配置。
0.1.1 新增接口兼容性检查，已对两版模块样本和合成地址迁移、歧义及字段变化进行离线验证。
这不等于已在你的双人游戏中验证成功；本次运行就是为获得该证据。

结束后
禁用本诊断包，重新部署，即可恢复日常使用。正式换座包及其 INI 保留。
